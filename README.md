# CS-340-Client-Server-Development
Python and MongoDB full stack project

----------------------------------------------------------------
  **How do you write programs that are maintainable, readable, and adaptable? Especially consider your work on the CRUD Python module from Project One, which you used to connect the dashboard widgets to the database in Project Two. What were the advantages of working in this way? How else could you use this CRUD Python module in the future?**

I think the best way to keep code maintainable is to keep it organized and avoid repeating code whenever possible. The CRUD module from Project One was a good example of this. Instead of writing the database operations directly into the dashboard, I was able to reuse the module from Project One. This made the dashboard easier to work with and allowed me to make changes to the database operations without changing the dashboard itself.
I could see using a similar module in future projects that require database interactions. The data and queries might be different, but the basic functionality would remain the same.

  **How do you approach a problem as a computer scientist? Consider how you approached the database or dashboard requirements that Grazioso Salvare requested. How did your approach to this project differ from previous assignments in other courses? What techniques or strategies would you use in the future to create databases to meet other client requests?**

I generally try to break problems down into smaller tasks and work through them one at a time. This project followed that approach pretty well. We started by importing the data into MongoDB, then built the CRUD module, and finally connected everything to the dashboard.
One difference from previous courses was that we weren't just writing code to complete individual assignments. Each assignment built toward a larger project with specific requirements from a client. In the future, I would use a similar approach, starting with understanding the client's requirements and then breaking the project into smaller, manageable tasks.
